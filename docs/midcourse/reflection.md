# Reflection — Mid-Course Project

Working on this mid-course project reinforced how valuable a slow, step-by-step AI-assisted workflow is when you're not a programmer yourself. Rather than asking the assistant to generate the whole feature in one shot, I had it walk me through one small change at a time — one field, one function, one test — and I verified each step before moving to the next. This made the process feel manageable even under a tight deadline, and it meant that when something did break, I could immediately narrow down where the problem was instead of debugging a wall of unfamiliar code.

The two features I chose, tags/labels and due dates with an overdue filter, were deliberately picked as the simplest options given the time constraint. In hindsight this was the right call: both features only required adding new fields to existing models rather than introducing new relationships, entities, or state machines. This kept the backend changes small and easy to reason about, even though I don't code myself.

The most useful skill this project reinforced was verifying claims independently rather than trusting that a copy-pasted change worked just because the assistant said so. Twice during this project, a manual copy-paste introduced a bug: once a duplicated variable declaration and mismatched indentation in `storage.py`, and once a deleted JSON body inside a test function that caused a test to silently merge into the one above it. In both cases, VS Code's Problems panel and the actual pytest output were what caught the issue, not confidence in the code looking "probably right." Reading the real error location and the real terminal output was what let me communicate the actual bug back and get a precise fix, rather than guessing.

Testing manually through the Swagger UI before writing automated tests was also valuable. Seeing the actual JSON response with `is_overdue: true` for a past due date, and confirming the tag filter returned only matching tasks, gave me confidence the logic was correct before I asked for pytest tests to lock that behavior in. This two-step verification (manual, then automated) meant the 25 passing tests at the end felt like confirmation of something I'd already seen work, not a leap of faith.

If I did this again with more time, I would have liked to add a small UI element for filtering the board by tag or overdue status directly (the backend already supports it via query params), rather than only testing those filters through Swagger. But given the deadline, prioritizing correctness and test coverage over UI polish for the filter itself was the right tradeoff.
